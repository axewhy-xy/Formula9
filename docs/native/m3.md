# M3: Complete native training MVP

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. NAT-M3-10 through NAT-M3-12 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Earlier optional detail/ECS or fallback language cannot waive the primary 3D world required from M2. New tasks remain planned until verified.

Status: planned. Depends on [M2](m2.md) and the shared M3 contracts.

## Outcome

A trainee completes a repeatable shift with time-windowed closures, concurrent incidents, route changes, and charge/swap scheduling. A trainer creates a small valid scenario, runs it, and reviews an exportable debrief entirely through the native application.

All five product screens reach functional parity with the app. Detailed ECS presentation can improve inspection but cannot hide a workflow that exists only in another client.

## Dependencies

| Input | Required contract or artifact |
| --- | --- |
| Backend | Route drafts/revisions, time windows, avoid zones, proposal expiry, concurrent incident state, atomic charge/swap proposals |
| Backend review | Immutable checkpoints/event history, versioned scoring rubric, report artifacts and source manifests |
| Product | Training tasks and accepted alternatives, minimum coverage/reserve assumptions, instructor/trainee permission model |
| Web | Shared scenario authoring fields, command conflict cases, provenance and review-mode conventions |

## Tasks

### NAT-M3-01: Structured route editing

**Dependencies:** [NAT-M2-04](m2.md#nat-m2-04-pre-trip-route-editing), [BE-M3-01](../backend/m3.md#be-m3-01-complete-pre-trip-planning-and-validation).

**Required inputs:** Versioned drafts, timed closure semantics and avoid-area fixtures.

**Planned blockers / completion gates:** Unknown/failed mandatory checks must prevent approval; local undo/redo cannot change an already approved route.

- Add versioned route drafts, undo/redo in local draft state, time-windowed segment closures, and graph-constrained avoid-area editing.
- Preserve the approved route while editing; show draft/reviewed/queued/applied/rejected as distinct states.
- Display turn/one-way/fit/stop/operating-area validation by affected segment and route; select a failed check to locate the problem.
- Review original/proposed duration, distance, stop changes, energy, and affected assignments before submitting a reasoned approval.

Output: versioned route-draft editor with undo/redo, timed closures, avoid areas, per-segment validation, and approval comparison.

Verification: closure boundaries, invalid polygons, wrong-way paths, and missed stops produce actionable backend results; undo/redo never changes the approved route, and failed or unknown mandatory checks cannot enable approval.

### NAT-M3-02: Asynchronous validation and proposals

**Dependencies:** [NAT-M3-01](m3.md#nat-m3-01-structured-route-editing), [BE-M3-01](../backend/m3.md#be-m3-01-complete-pre-trip-planning-and-validation), [BE-M3-02](../backend/m3.md#be-m3-02-complete-in-trip-decision-management).

**Required inputs:** Bounded jobs, request generations and isolated preview contracts.

**Planned blockers / completion gates:** Out-of-order validation must never enable stale approval; timeout/cancel preserves drafts and preview inspection cannot advance the live fleet.

- Debounce route edits and tag each request with draft revision and request generation; discard stale responses.
- Cancel obsolete requests and bound pending jobs; show computing/cancelled/unavailable distinctly from invalid.
- Render candidate alternatives with proposal revision, expiry, supported actions, and consequences supplied by the backend.
- Offer a bounded simulate-before-approve branch from a committed checkpoint; label projected results, leave live fleet state and timers unchanged, and invalidate the preview when relevant source revisions change.
- Preserve a rejected draft for correction; refresh constraints explicitly instead of silently approving a different path.

Output: debounced/cancellable proposal pipeline, revision-tagged alternatives, isolated simulate-before-approve view, and bounded pending-job handling.

Verification: deliberately reordered replies cannot restore an older draft or enable its approval; timeout/cancellation preserve editable work, and preview creation/inspection leaves live fleet state and timers unchanged while changed source revisions invalidate the preview.

### NAT-M3-03: Concurrent incident workspace

**Dependencies:** [NAT-M2-05](m2.md#nat-m2-05-incident-focus-and-response), [NAT-M3-02](m3.md#nat-m3-02-asynchronous-validation-and-proposals), [BE-M3-02](../backend/m3.md#be-m3-02-complete-in-trip-decision-management).

**Required inputs:** Concurrent incident fixtures and per-incident command state.

**Planned blockers / completion gates:** Needs stable selection and peer invalidation during concurrent changes; commands must stay bound to the selected live incident/revision.

- Sort/filter incidents by severity, age, shuttle, and unresolved status without stealing selection as updates arrive.
- Support several open incident detail views or a stable pinned selection, with per-incident pending command state.
- Add manual graph-constrained detour, wait, escalation, and valid candidate approval with reason and current revision checks.
- Show route/charge/incident changes caused by another client, including who acted and whether the current proposal became stale.

Output: sortable incident workspace with stable selection, per-incident command state, manual detour/wait/escalation actions, and peer-change notices.

Verification: simultaneous incidents remain independently actionable without focus theft; resolving one from web invalidates native's stale action, and every remaining command targets the selected incident and correct revision.

### NAT-M3-04: Charging timeline and swap workflow

**Dependencies:** [NAT-M2-06](m2.md#nat-m2-06-basic-battery-and-charging-choice), [BE-M3-03](../backend/m3.md#be-m3-03-implement-battery-and-charging-operations).

**Required inputs:** Atomic swap/reservation APIs and keyboard timeline equivalents.

**Planned blockers / completion gates:** Backend depot/reserve/coverage constraints must drive outcomes; partial swaps, overlap and local success before commit block acceptance.

- Build a time-scaled shuttle and charger schedule with rounds, charging, standby, reservations, maintenance, and proposed intervals.
- Review a backend-computed swap as one transaction: replacement assignment, return-to-depot travel, charge slot, reserve, and service coverage.
- Expose interval conflicts, unavailable chargers, uncovered stops/headways, and insufficient reserve as structured issues.
- Provide keyboard-editable times and accessible list equivalents; keep dragging provisional until validated and applied.

Output: accessible shuttle/charger timeline, swap review, structured constraint display, and atomic-plan approval presentation.

Verification: keyboard and drag proposals yield the same backend plan; double-booking, maintenance, low reserve, and coverage-conflict fixtures cannot produce partial applied swaps, and rejected proposals leave the last confirmed schedule intact.

### NAT-M3-05: Recorded lead-up and immutable review

**Dependencies:** [NAT-M2-05](m2.md#nat-m2-05-incident-focus-and-response), [BE-M3-02](../backend/m3.md#be-m3-02-complete-in-trip-decision-management).

**Required inputs:** Paged immutable checkpoints/events and per-item source intervals.

**Planned blockers / completion gates:** History must remain bounded and independent from live control/alerts; missing media and earliest world divergence cannot create false recorded continuity.

- Add live/follow and review cursors with a prominent return-to-live control; browsing history cannot change active dispatch selection implicitly.
- Page bounded history ranges from immutable checkpoints and ordered events instead of retaining an entire shift in RAM.
- Synchronize selected shuttle, incident evidence, map, optional ECS view, and source frame to one review time.
- Mark source intervals, missing footage, source geography, and continuation per entity; earliest world divergence ends recorded-camera continuity, including pre-trip edits.
- Suppress replayed historical alerts while preserving current live incident alerts and return-to-live; historical inspection does not pause the live fleet.

Output: bounded paged review store, synchronised evidence cursor, per-entity source intervals, and return-to-live navigation with independent live alerts.

Verification: seeking across missing history or a branch never substitutes incompatible camera footage; review does not mutate/pause the live shift, historic events do not retrigger audio, and new live incidents remain visible during inspection.

## Additional 3D exit criteria

- The full native training/authoring workflow runs in 3D, including surface-aware edits, placement, depot execution and correctly labelled synthetic review.
- Multi-level/headroom and scene/branch isolation cases pass with the same spatial revisions as backend/web.
- Mandatory P1 passes with the primary 3D view and required inset active; earlier 2D-only evidence is insufficient.

## Failure cases to exercise

- Two clients reserve the same charger, approve conflicting routes, or resolve one incident concurrently; only the backend winner appears applied.
- A closure activates while a proposal is being reviewed; approval revalidates and can reject the stale proposal.
- A route draft changes while its older validation completes; the old result cannot enable approval.
- History is missing, footage unavailable, export interrupted, or a source asset corrupt; the active shift remains usable.
- A timeline seek cannot submit commands against historical state, pause the live fleet, suppress current incidents, or generate duplicate historical audio.
- Moving between scenarios during decode/download cancels stale work and cannot upload old assets into the new GL view.

## Deliverables and exit evidence

- A native training MVP covering the five screens, minimal trainer authoring, history review, and report export.
- Automated contract/model tests plus recorded human interaction checks for keyboard, DPI, themes, and OpenGL lifecycle.
- Cross-client evidence from a complete shift with concurrent incidents and a charge/swap conflict.
- Passing mandatory P1 results with raw performance traces; unresolved required-budget misses block M3 acceptance. All functional consistency and provenance defects are resolved.
- A new trainee completes pre-trip preparation, incident response, charging intervention, and debrief without developer assistance.
