# M2: Native fleet-training vertical slice

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. NAT-M2-09 through NAT-M2-11 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Earlier optional detail/ECS or fallback language cannot waive the primary 3D world required from M2. New tasks remain planned until verified.

Status: planned. Complete this milestone before expanding scenario variety.

## Outcome

A trainee uses the native application to prepare a loop, supervise five shuttles, resolve one incident, make a basic charging decision, and inspect a recorded result. A simultaneous web client sees the same session and applied actions.

Fixture scope: five shuttles, three routes, two chargers, one active incident, a static closure, a backend-approved node detour, and a simple battery-reserve choice. The canonical P1 workload and measurement procedure are defined in [performance](../performance.md).

## Dependencies

| Input | Required contract or artifact |
| --- | --- |
| Backend | Versioned fleet/session snapshot, ordered events, idempotent commands, route validation/proposals, battery state, incident records, simple score |
| Web | Shared terminology, five-screen acceptance script, status/provenance styles, common JSON fixtures |
| Product | Curated M2 scenario, reference choices and scoring rubric, supported window/DPI configuration |
| Build | Pinned compiler/Qt/OpenGL configuration and repeatable Release build procedure |

### NAT-M2-02: Bounded transport and command state

**Dependencies:** [NAT-M2-01](m2.md#nat-m2-01-typed-domain-and-one-authoritative-session), [BE-M2-03](../backend/m2.md#be-m2-03-persist-commands-and-recoverable-state).

Verification: duplicate events, sequence gaps, overflow, lost acknowledgements, and backend restart leave one authoritative outcome; stale state blocks decisions, and recovered approvals require reconfirmation rather than automatic resubmission.

## Additional 3D exit criteria

- NAT-M2-09 through NAT-M2-11 pass: the complete slice runs in the primary 3D viewport with dimensioned content, required cameras and working scene interaction.
- Transform, support, obstruction and pick fixtures pass against the shared contract and web/backend reference.
- M2 captures a real 3D P1 baseline; optional inspection/fallback cannot replace the mandatory operational world.

## Failure cases to exercise

- A malformed/oversized payload, unknown required schema, old session callback, or missing snapshot baseline cannot mutate the visible fleet.
- A duplicate event/command receipt produces one log entry; an out-of-order event produces resync, not a silently skipped audit record.
- A web approval invalidates a native proposal; native shows a conflict and requires renewed review.
- Network loss after submission preserves an unknown/pending result until reconciled; reconnect cannot create a second approval or apply an old decision requiring reconfirmation.
- An invalid one-way route, missing fit metadata, charger unavailable, and reserve violation are explained consistently with the app.
- Closing during chunk download, GL upload preparation, or a pending command leaves no callback targeting a destroyed widget.
- Repeated route selections and view switching cannot grow trail/history or decoded-asset memory without a bound.

## Deliverables and exit evidence

- Release executable plus a reproducible M2 fixture and a five-screen walkthrough using real backend state.
- Typed contract fixtures/tests, command-state diagram, queue limits, and native owner-thread/cancellation notes.
- Native/web parity record for the same route revision, incident outcome, charging decision, and simple score.
- Measured P1 baseline with frame target p95/p99 16.7/33.3 ms and authoritative state-age target 250/500 ms; misses have traces and owners.
- Demonstrate the whole slice without developer JSON, hidden commands, or client-side authoritative decisions.

M2 establishes measured baselines; P1 performance gates become mandatory in M3 and must be preserved in M4. M5 adds extended stress, soak, and fault gates. Missing product flow or incorrect command/provenance behaviour blocks M2 even if animation is smooth.
