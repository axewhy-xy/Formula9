# M5: Native feature completeness, recovery, and performance

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. NAT-M5-10 through NAT-M5-12 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Earlier optional detail/ECS or fallback language cannot waive the primary 3D world required from M2. New tasks remain planned until verified.

Status: planned. Depends on accepted M4 scope and frozen candidate contracts.

## Outcome

The complete native training workflow remains responsive through long shifts, concurrent activity, network failures, and repeated view/session changes. Performance limits are backed by reproducible evidence and a recoverable user experience.

The [performance contract](../performance.md) is authoritative for P1/P2 workload definitions and target interpretation. Proposed numbers become acceptance evidence only after measurement on the declared reference hardware.

### NAT-M5-02: Native rendering performance

**Dependencies:** [NAT-M4-10](m4.md#nat-m4-10-extend-environment-fidelity-without-changing-authority), [NAT-M4-12](m4.md#nat-m4-12-compare-and-profile-spatial-training-branches).

**Required inputs:** Fixed viewport/DPI and CPU/GPU profiling tools.

**Planned blockers / completion gates:** Optimization needs baseline/after traces at the same workload; optional-detail reduction cannot hide decisions or required geometry to meet frame budgets.

- Profile CPU frame, GPU frame, draw calls, static geometry rebuilds, entity updates, label/layout work, and upload stalls independently.
- Batch static geometry, reuse meshes, instance fleet symbols, cull off-screen detail, and update dynamic buffers by dirty range.
- Bound work per frame and retain responsive controls during chunk preparation; reduce optional detail before degrading decision visibility.
- Meet P1 p95/p99 frame targets of 16.7/33.3 ms at the documented viewport/DPI and retain reproducible traces for regressions.

Output: measured rendering optimisations, CPU/GPU stage profiles, frame-work limits, and before/after P1 traces at the declared viewport/DPI.

Verification: P1 frame intervals meet p95/p99 16.7/33.3 ms while the full workflow remains correct; scene preparation stays bounded, and any optional-detail reduction preserves incident visibility, selection, and decision controls.

### NAT-M5-03: Resource ceilings and lifecycle

**Dependencies:** [NAT-M4-08](m4.md#nat-m4-08-work-scheduling-and-fault-isolation), [NAT-M4-12](m4.md#nat-m4-12-compare-and-profile-spatial-training-branches).

**Required inputs:** Item/byte ceilings, revision-keyed caches and two-hour lifecycle script.

**Planned blockers / completion gates:** Memory/queues must plateau through session/view/context churn; invalid-context destruction or assets crossing revisions block acceptance.

- Publish concrete item/byte ceilings for event buffers, snapshots, history pages, prepared geometry, textures, trails, and audio channels.
- Implement cache eviction with session/revision-aware keys and bounded in-flight asset downloads/decode/upload queues.
- Test repeated create/join/leave, window open/close, tab changes, minimized/background use, and frame-history scrubbing for memory plateau.
- Release GL resources only with a valid owning context; handle `aboutToBeDestroyed` and rebuild after context recreation where supported.

Output: item/byte resource-budget table, revision-aware eviction, bounded asset queues, GL destruction/recreation handling, and lifecycle/soak resource graphs.

Verification: repeated session/view/scrub cycles and the two-hour P1 soak meet the canonical memory-plateau and resource limits; no asset crosses session/revision boundaries, and GL recreation releases/rebuilds resources without invalid-context access.

### NAT-M5-04: Robust transport and event recovery

**Dependencies:** [NAT-M2-02](m2.md#nat-m2-02-bounded-transport-and-command-state), [NAT-M3-09](m3.md#nat-m3-09-mvp-parity-and-measured-performance).

**Required inputs:** BE-M5-03/04 replay/restart cases and cached-reconnect profile.

**Planned blockers / completion gates:** Wrong epochs, retention expiry and late responses must resynchronize safely; cached recovery must meet the canonical two-second p95 gate.

- Add bounded reconnect backoff/jitter and explicit offline/stale/resyncing/live states with a visible last authoritative update.
- Resume from the last durable event sequence; recover from replay-window expiry using a consistent full snapshot plus event cursor.
- Detect mismatched epoch/base revision, duplicate receipts, late HTTP responses, and conflicting streams before store mutation.
- Meet cached reconnect recovery p95 at or below two seconds under the canonical recoverable-network test after connectivity returns.

Output: bounded reconnect state machine, durable-cursor resume/full-resync paths, freshness indicators, and recovery timing traces.

Verification: event gaps, expired replay windows, wrong epochs, duplicate receipts, and late responses cannot corrupt the store; clients converge on committed state, with cached recovery p95 at or below two seconds after connectivity returns under the canonical test.

### NAT-M5-05: Fault-safe command handling

**Dependencies:** [NAT-M5-04](m5.md#nat-m5-04-robust-transport-and-event-recovery), [NAT-M3-02](m3.md#nat-m3-02-asynchronous-validation-and-proposals), [NAT-M3-03](m3.md#nat-m3-03-concurrent-incident-workspace), [NAT-M3-04](m3.md#nat-m3-04-charging-timeline-and-swap-workflow).

**Required inputs:** Original command IDs and backend acceptance/application fault injection.

**Planned blockers / completion gates:** Lost replies, revoked roles or missing history cannot fabricate success or auto-apply recovered approvals; changed consequences require renewed review.

- Simulate connection loss before receipt, after `QUEUED`, and after `APPLIED`; reconcile by original command ID without a duplicate side effect.
- Prevent stale/offline decision submission and invalidate expired proposals; any unsent local draft requires fresh review after resync.
- Preserve rejected reasons and safe editable drafts without turning retries into implicit approval of changed consequences.
- Test backend restart, session ended, role revoked, and unavailable command history; old queued commands show `NEEDS_RECONFIRMATION`/expired on recovery, never surprise application.

Output: command uncertainty/reconciliation tests, safe draft preservation, reconfirmation UI, and a fault-stage matrix linked to original command IDs.

Verification: loss before receipt, after queuing, and after application produces at most one authoritative side effect; restart, role revocation, and missing history never fabricate success or automatically apply stale approvals, and changed consequences require renewed review.

### NAT-M5-06: Latency and pressure validation

**Dependencies:** [NAT-M5-02](m5.md#nat-m5-02-native-rendering-performance), [NAT-M5-03](m5.md#nat-m5-03-resource-ceilings-and-lifecycle), [NAT-M5-04](m5.md#nat-m5-04-robust-transport-and-event-recovery), [NAT-M5-05](m5.md#nat-m5-05-fault-safe-command-handling).

**Required inputs:** BE-M5-01 P1/P2/LAN setup and stage-correlated probes.

**Planned blockers / completion gates:** Requires raw complete-workflow timings and bounded-pressure behavior with both clients. Only specified command/state-age metrics receive the LAN allowance.

- Measure command acceptance 150/300 ms and applied-state visibility 250/500 ms p95/p99 on loopback under P1.
- Check the canonical LAN profile with RTT at most 40 ms; its additional 50 ms allowance applies only to command-to-visible latency and fleet state age. Keep all other budgets unchanged and record clock uncertainty.
- Verify state age 250/500 ms, route validation 300/750 ms, and candidate generation 1/2 s p95/p99 with evidence from all pipeline stages.
- Run P2 with 50 shuttles, 10,000 directed edges, and ten subscribers; document supported limits, pressure effects, and explicit overload behaviour.

Output: reproducible loopback/LAN P1 and P2 pressure reports with raw percentile samples, clock uncertainty, stage timings, and supported-capacity/degradation findings.

Verification: all mandatory P1 budgets and P2 correctness, recovery, and bounded-resource checks pass under their defined workloads; the LAN allowance applies only to command-to-visible latency and state age, and indicative P2 speed misses are disclosed with measured limits.

### NAT-M5-08: Shutdown and worker correctness

**Dependencies:** [NAT-M4-08](m4.md#nat-m4-08-work-scheduling-and-fault-isolation), [NAT-M5-03](m5.md#nat-m5-03-resource-ceilings-and-lifecycle).

**Required inputs:** QObject/thread ownership map, bounded shutdown policy and fault harness.

**Planned blockers / completion gates:** Closing during network/decode/upload must avoid deadlock, use-after-free and stale mutation; optional audio/media failure cannot prevent clean exit.

- Document QObject/thread ownership and ensure network objects remain in their owning event-loop thread.
- Guard every async view callback with `QPointer`/generation checks; cancel work before releasing domain store or renderer state.
- Join worker pools within a declared bounded shutdown interval; do not block the GUI waiting indefinitely for downloads.
- Verify FMOD/device failure and optional-media exceptions cannot corrupt live state or prevent a clean exit.

Output: QObject/worker ownership map, guarded callback/cancellation paths, declared shutdown timeout, and fault-injected shutdown results.

Verification: closing or switching sessions during network/decode/upload work finishes within the declared bound without deadlock, use-after-free, or cross-session mutation; audio/device and optional-media failures cannot prevent clean exit or corrupt durable state.

## Additional 3D exit criteria

- Native passes mandatory P1 using the frozen 3D content/quality/camera workload with both clients visible.
- Two-hour asset/context/session churn demonstrates bounded resources, correct readiness and no cross-scene or command-state corruption.
- Spatial and 3D accessibility regressions are closed before release; a usable text fallback does not waive failed normal 3D rendering.

## Fault and soak matrix

- Run a two-hour P1 mixed-workflow soak and repeated-session loops; record resident/GPU memory plateau, queue high-water marks, and error rates.
- Introduce latency, jitter, disconnects, event gaps, duplicate messages, oversized/corrupt payloads, and slow asset responses.
- Saturate optional detail/media work while resolving an incident and scheduling a swap; important events remain ordered and recoverable.
- Restart the backend and recreate a GL context during active/review modes; verify expected state, no surprise approvals, and no cross-session assets.
- Execute two-client conflicting approvals, charge reservations, and role changes with a single authoritative applied outcome.

## Deliverables and exit evidence

- Feature-complete Release candidate, candidate contract manifest, supported-limit statement, and updated user/trainer guidance.
- P1 acceptance measurements and P2 pressure report with raw samples/traces, hardware, build, scene, network, duration, and warm/cold labels.
- Fault/soak report, queue/cache limits, shutdown/context-lifecycle results, and native/app parity evidence.
- No unresolved blocker/critical defect; any lower-priority exception has impact, workaround, owner, and beta disposition.
- All mandatory P1 gates and P2 correctness, recovery, and bounded-resource checks pass. Report indicative P2 speed results and measured supported capacity separately, including tail latency and overload behaviour.
