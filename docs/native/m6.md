# M6: Native beta packaging and acceptance

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. NAT-M6-10 through NAT-M6-12 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Earlier optional detail/ECS or fallback language cannot waive the primary 3D world required from M2. New tasks remain planned until verified.

Status: planned. Depends on the accepted [M5 release candidate](m5.md).

## Outcome

A clean supported Windows machine installs and runs the native beta, joins a training session, completes every approved core workflow, and exports a reproducible debrief. The released client and web application agree on all authoritative state and outcomes.

M6 freezes and validates the beta. New features return to scope review; only fixes and required release work enter the candidate.

## Dependencies

| Input | Required contract or artifact |
| --- | --- |
| Backend | Release deployment, schema/artifact versions, backup/restore and recovery runbook, accepted scenario catalogue |
| Web | Same release contract/fixtures, paired-client acceptance availability, supported browser counterpart |
| Product | Approved training scripts, rubric, usability participants, documented acceptance and issue-severity definitions |
| Release | Toolchain/runtime/license inventory, supported hardware matrix, distributable assets and package checksums |

## Tasks

### NAT-M6-01: Freeze the release manifest

**Dependencies:** [NAT-M5-01](m5.md#nat-m5-01-feature-and-contract-closure), [NAT-M5-09](m5.md#nat-m5-09-build-and-package-rehearsal), [NAT-M5-12](m5.md#nat-m5-12-close-3d-interaction-and-spatial-regressions).

**Required inputs:** Accepted M5 gates, runtime/driver inventory and backend/web compatibility pins.

**Planned blockers / completion gates:** Candidate identity and supported-capacity claims must match evidence; incomplete optional features stay disabled and required content remains mandatory.

- Freeze client version, commit/build identity, schema support, scenario/rubric/map revisions, and optional feature flags.
- Record compiler, Qt, OpenGL requirements, audio runtime mode, supported Windows versions, and tested graphics drivers.
- Publish the supported P1 configuration and observed P2 limits with the measurement artifacts from M5.
- Remove incomplete optional features from the default workflow and document deferred scope without obscuring core functionality.

Output: frozen release/compatibility manifest, supported hardware/runtime matrix, measured load-envelope statement, and explicit optional-feature dispositions.

Verification: package, schema, scenario, rubric, and map identities match the accepted candidate and evidence; no incomplete optional feature is enabled by default, and supported-capacity claims trace to recorded measurements.

### NAT-M6-02: Reproducible distributable

**Dependencies:** [NAT-M6-01](m6.md#nat-m6-01-freeze-the-release-manifest), [NAT-M5-09](m5.md#nat-m5-09-build-and-package-rehearsal).

**Required inputs:** Redistributable Qt/plugins/runtimes/assets, licenses and standard-user package paths.

**Planned blockers / completion gates:** Must launch outside the source tree with all required dependencies and checksums. Signing is required only if an approved signing process exists; unavailable signing is not an invented blocker.

- Produce a Release package with executable, required Qt plugins/runtimes, shaders, assets, default configuration, and permitted FMOD components.
- Include dependency/license notices and source/data attribution, including the actual provenance of recorded sequences.
- Publish package checksums; sign if an approved signing process exists, without making unavailable signing infrastructure an implied prerequisite.
- Ensure first launch, shader/media lookup, logs, and settings work from a non-developer directory and standard user account.

Output: versioned native Release package, checksums, configuration/assets, dependency/license notices, source attribution, and signing status where applicable.

Verification: checksums match the delivered artifacts, all required runtime/plugin/assets resolve from the package, and a standard account can launch from outside the source tree without undeclared developer dependencies.

### NAT-M6-03: Connection and diagnostics experience

**Dependencies:** [NAT-M6-01](m6.md#nat-m6-01-freeze-the-release-manifest), [NAT-M5-04](m5.md#nat-m5-04-robust-transport-and-event-recovery), [NAT-M5-05](m5.md#nat-m5-05-fault-safe-command-handling).

**Required inputs:** Released endpoint/auth/version contracts and redacted diagnostic policy.

**Planned blockers / completion gates:** Setup and trust/version failures need actionable guidance; diagnostics must remain bounded and omit credentials/unnecessary personal data.

- Provide backend endpoint configuration, supported authentication flow, actionable incompatible-version errors, and a safe reconnect experience.
- Display release/session/scene/scenario revisions plus connection freshness without exposing credentials or unnecessary personal data.
- Offer a bounded, redacted diagnostics export containing build, hardware, event/command references, errors, and performance summaries.
- Document proxy/firewall/TLS trust failures and missing runtime/graphics problems with precise corrective steps.

Output: endpoint/authentication setup, actionable connection/version errors, revision/freshness display, redacted bounded diagnostics export, and connectivity troubleshooting notes.

Verification: valid configuration joins the intended session; invalid credentials, incompatible versions, and trust/network failures produce distinct recovery guidance. Diagnostics identify the build/session evidence without credentials or unnecessary personal data and stay within their declared bound.

### NAT-M6-04: Clean-machine and upgrade acceptance

**Dependencies:** [NAT-M6-02](m6.md#nat-m6-02-reproducible-distributable), [NAT-M6-03](m6.md#nat-m6-03-connection-and-diagnostics-experience).

**Required inputs:** Clean supported machines, prior candidate settings and upgrade/removal policy.

**Planned blockers / completion gates:** Install/restart/upgrade must work under supported permissions; dependency/configuration failures must be clear and removal must preserve user-created exports.

- Validate extract/install, first launch, backend connection, session join, closure, restart, and removal on clean supported machines.
- Verify upgrade from the prior candidate preserves only compatible preferences and clearly migrates/resets invalid settings.

- Confirm removal instructions identify generated logs/settings separately so user-created exports are not deleted accidentally.

Output: clean-machine installation/upgrade/removal test matrix, compatible-preference migration results, and corrective guidance for packaging/environment failures.

Verification: documented install-to-training and restart paths work on supported machines; invalid settings, missing dependencies, unsupported graphics, and unwritable exports fail clearly, and removal preserves user-created reports according to the documented procedure.

## Additional 3D exit criteria

- Clean-machine native operation includes the mandatory 3D world and all spatial workflows, with the released scene/profile manifest.
- Final P1/spatial conformance and four-hour 3D soak/recovery pass with packaged backend/web parity.
- Observed 3D usability, accessibility and updated guidance are delivered; any failure of mandatory 3D remains release-blocking.

## Release-blocking failures

- Any core action can appear applied before authoritative confirmation, produce duplicate side effects, or target the wrong session/revision.
- Recorded footage is presented as synthetic-route observation or as footage from a geography it does not represent.
- The native client and app disagree on applied route/charge state, durable incident record, score, or report identity.
- A clean supported machine cannot complete the training workflow without developer tooling or hidden source-checkout dependencies.
- Mandatory P1 performance/recovery gates fail on the declared reference configuration or resource use grows without a defined bound.
- A blocker/critical correctness, crash, data-loss, or accessibility defect remains unresolved.

## Deliverables and exit evidence

- Versioned beta package, checksum/dependency/license manifests, supported-platform statement, and installation/upgrade instructions.
- Final native acceptance report with scenario IDs, run IDs, command/event references, build identity, and native/app parity results.
- Final performance and four-hour soak report, clean-machine evidence, accessibility/usability observations, and fault-recovery results.
- Trainee/trainer guides, support runbook, release notes, known-issue register, and deferred backlog.
- All mandatory acceptance gates pass and the product/technical reviewers can reproduce the core demonstration from the released artifacts.

Beta acceptance establishes the quality of the training application under the stated assumptions. Its simulated choices, vehicle behaviour, and scores do not establish real-world operational approval or AV safety certification.
