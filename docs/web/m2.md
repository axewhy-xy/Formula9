# M2: Complete small fleet training exercise

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. WEB-M2-07 through WEB-M2-09 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Primary 3D is required from M2; 2D panels/minimaps and accessible fallback support but cannot replace it. New tasks remain planned until verified.

## Outcome and scope

A trainee can review three routes for five shuttles, edit around a static closure, approve a validated route with a reason, respond to one incident, make a basic charging choice and open a simple debrief. Two chargers and a scripted reserve/coverage conflict make the charging decision meaningful.

All five rough concept screens become connected, usable surfaces. This is a thin exercise with real server state and limited authoring; advanced map geometry, scheduling and analytics belong to later milestones.

Dependencies: [backend M2](../backend/m2.md), [native M2](../native/m2.md), the v2 contract fixtures and [performance profile P1](../performance.md).

## Tasks

### WEB-M2-01: Typed feature shell and common interaction language

**Dependencies:** [BE-M2-01](../backend/m2.md#be-m2-01-define-the-training-domain-and-versioned-contracts).

**Required inputs:** Shared five-screen terminology, themes, focus and session/selection conventions.

**Blockers / remaining gates (28 October 2026):** Can start against fixtures. Completion requires every feature to retain the same session/entity identity; isolated feature workspaces do not establish shell acceptance.

- Split route preparation, fleet overview, incident response, charging plan and debrief into typed feature modules with persistent session navigation.
- Preserve the existing three.js adapter and coordinate checks while replacing the single-ego information hierarchy with a selected fleet entity.
- Implement light/dark tokens, body text at least 14 px, visible focus, legible status badges and icon/text alternatives to colour.
- Add a compact shared session bar with training status, simulation time, connection freshness and current actor role.
- Keep product messages understandable without exposing transport internals; provide expandable diagnostics for development.

Output: typed five-feature shell, persistent session navigation/bar, fleet-aware rendering adapter, and common theme/status/focus components.

Verification: all five views retain the same selected session and entity identity; both themes meet the stated text/focus requirements, status is understandable without colour alone, and coordinate/adapter checks still pass after replacing single-ego assumptions.

### WEB-M2-02: Authoritative command and stream foundation

**Dependencies:** [BE-M2-01](../backend/m2.md#be-m2-01-define-the-training-domain-and-versioned-contracts), [BE-M2-03](../backend/m2.md#be-m2-03-persist-commands-and-recoverable-state).

**Required inputs:** BE-M2-02 live publication and authenticated session access.

**Blockers / remaining gates (28 October 2026):** Live session APIs now exist. Prove bounded stream handling and shared command reconciliation through stale state, lost acknowledgements and restart; feature-local ledgers alone do not close this task.

- Implement v2 schema validation, request cancellation for reads, incompatible-version errors and a legacy replay boundary.
- Maintain a command ledger keyed by idempotency key and server command ID; expose accepted/queued, applied, rejected, needs-reconfirmation and unknown outcomes.
- Attach relevant expected session, route, incident or charging revisions to mutations; refresh on conflicts without losing a user's reason text.
- Separate ordered incident/command events from replaceable full position snapshots. If deltas are introduced, require a matching baseline before applying one.
- Establish worker ingestion, bounded snapshot/history queues, per-session connection epochs and state-store selectors; do not store every movement tick in root component state.
- Reuse the existing stale-socket guard and test that callbacks from an abandoned session cannot update the new session.

Output: validated v2 transport/store, worker ingestion, bounded event/snapshot queues, command ledger, and revision/epoch-aware cancellation and reconciliation.

Verification: malformed/foreign-session payloads, duplicate events, missing baselines, and obsolete callbacks cannot corrupt state; lost acknowledgements reconcile the original command without duplicate effects, and queued/unknown/reconfirmation states never appear applied prematurely.

### WEB-M2-03: Pre-trip route preparation

**Dependencies:** [WEB-M2-01](m2.md#web-m2-01-typed-feature-shell-and-common-interaction-language), [WEB-M2-02](m2.md#web-m2-02-authoritative-command-and-stream-foundation), [BE-M2-04](../backend/m2.md#be-m2-04-deliver-one-pre-trip-route-edit).

**Required inputs:** Curated closure/detour fixture and accessible node selection.

**Blockers / remaining gates (28 October 2026):** UI can use fixtures; connected visible route execution needs backend path replacement and 3D topology integration. WEB-M2-08 supplies the required 3D editing input for milestone acceptance.

- List three route assignments, affected shuttles and disruption reasons; prioritise routes that need action.
- Add one static segment closure, constrained node detour editing, undo/redo for the local draft and a keyboard-accessible node selector.
- Draw original and draft routes with different line styles and labels.

- Require a reason and a current validation result to request approval; expose the server-confirmed route revision and assigned shuttles after application.

Output: three-route preparation view, static-closure/node editor with keyboard alternative and undo/redo, validation/comparison panels, and reasoned approval flow.

Verification: the fixture detour can be completed without pointer-only actions; disconnected, wrong-way, mandatory-unknown, and stale edits cannot be approved, and the assigned shuttles display only the backend-confirmed route revision.

### WEB-M2-04: Fleet overview and bounded incident response

**Dependencies:** [WEB-M2-01](m2.md#web-m2-01-typed-feature-shell-and-common-interaction-language), [WEB-M2-02](m2.md#web-m2-02-authoritative-command-and-stream-foundation), [BE-M2-02](../backend/m2.md#be-m2-02-build-the-deterministic-five-shuttle-session-actor), [BE-M2-05](../backend/m2.md#be-m2-05-deliver-one-incident-and-one-battery-decision).

**Required inputs:** Source-labelled history, option expiry and incident explanation fixtures.

**Blockers / remaining gates (28 October 2026):** Live obstruction, incident identity, options and durable actor consequences are not yet one 3D workflow. Missing or incompatible recorded footage must remain explicitly unavailable.

- Show all five shuttle statuses, route assignments, state of charge and the single unresolved incident with elapsed decision time.
- Provide incident zoom and a ten-second history strip sourced from stored simulation events/snapshots; label unavailable prehistory honestly.
- Display the backend's plain-language explanation and permitted choices: wait, escalate or a validated road-network detour.
- Mark options as previewed, expired, rejected or available and preserve their scenario/world/incident revisions.
- Present simulated outcome previews separately from session simulation history or genuine recorded lead-up, using per-item source labels; never present a generated path as real camera evidence.
- Establish the branch at the first recorded-world change, including pre-trip edits; an incident after that branch cannot reuse the original camera as its current view.
- Collect the trainee's reason, submit one decision and track its authoritative outcome in both the detail view and fleet list.
- Keep local history inspection independent of shared simulation pause/resume and retain notifications for newly raised live incidents.

Output: five-shuttle overview, incident focus/actions, bounded ten-second history strip, independent preview/history/live modes, and per-item source labels.

Verification: wait/escalate/detour actions reconcile with the fleet list and backend; expired or wrong-incident proposals do not apply, new live alerts remain visible during review, and pre-trip divergence or missing prehistory cannot be represented by incompatible recorded footage.

Verification: reserve/coverage estimates and rubric values match the fixture's backend records; a conflicting charger request does not create a displayed reservation, and failed downloads or unavailable results are reported without fabricated success.

## Additional 3D exit criteria

- WEB-M2-07 through WEB-M2-09 deliver a navigable dimensioned 3D world and the connected fleet/route/incident/charging/debrief slice.

## Verification and failure cases

- Contract fixtures include unknown versions, wrong session IDs, malformed coordinates, missing delta baselines and duplicate durable events.
- Route workflow rejects disconnected edits and stale approval attempts; the pending request cannot silently overwrite a newer draft.
- Repeated approval clicks and a lost acknowledgement produce one backend mutation and one displayed audit record.
- Switching route or incident while a request is in flight cannot attach the result to the wrong entity.
- Pausing the local history cursor leaves the live shift and the other client running, and new live incidents remain visible.
- A disconnect after submission shows an unknown outcome until reconciliation; no successful outcome is fabricated.
- Missing recorded images, missing history and renderer failure leave usable textual incident details.
- Keyboard users can choose a detour, enter a reason and complete the exercise without pointer-only actions.

## Deliverables and exit evidence

- Typed v2 client/store foundation, reusable feature shell and all five connected training views.
- One versioned P1 exercise and browser integration script that covers route approval, incident decision, charge choice and debrief.
- Screenshot/video evidence in both themes with actual backend data and visible provenance labels.
- A paired web/native run showing consistent route revision, incident resolution and battery/reservation state.
- Initial latency/frame/memory report with hardware, browser, fixture revision and sample counts; unmeasured targets remain labelled targets.
- Existing meaningful frontend checks plus `npm run typecheck`, `npm test` and `npm run build` pass on the milestone commit.

M2 exits only when the complete exercise works without manually editing JSON or using developer tools. A polished map without the route-to-debrief workflow is insufficient.
