# M5: Feature complete, responsive and resilient

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. WEB-M5-07 through WEB-M5-09 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Primary 3D is required from M2; 2D panels/minimaps and accessible fallback support but cannot replace it. New tasks remain planned until verified.

## Outcome and scope

All beta workflows are implemented and the web client remains usable under a large fleet, long training shifts, slow assets and interrupted connectivity. This milestone closes defects and demonstrates limits rather than adding a new product direction.

Dependencies: [web M4](m4.md), [backend M5](../backend/m5.md), [native M5](../native/m5.md), frozen candidate schemas and [performance.md](../performance.md).

## Tasks

### WEB-M5-01: Feature completion and contract freeze

**Dependencies:** [WEB-M3-09](m3.md#web-m3-09-complete-3d-charging-execution-and-p1-acceptance), [WEB-M4-01](m4.md#web-m4-01-advanced-shift-authoring), [WEB-M4-02](m4.md#web-m4-02-reference-solutions-and-transparent-scoring), [WEB-M4-03](m4.md#web-m4-03-debrief-patterns-and-trainer-review), [WEB-M4-07](m4.md#web-m4-07-rehearse-richer-3d-scene-variants), [WEB-M4-08](m4.md#web-m4-08-explain-3d-visibility-and-branch-consequences), [WEB-M4-09](m4.md#web-m4-09-expand-3d-quality-within-bounded-rendering).

**Required inputs:** Coordinated backend/native candidate schema and mandatory feature matrix.

**Planned blockers / completion gates:** All required workflows/error states must close; optional perception/manoeuvres may be disabled. Final contract freeze is coordinated with BE-M5-06, not a wait for its entire report.

- Close the approved workflow matrix for pre-trip preparation, fleet triage, incident decisions, charging, trainer authoring and debrief.
- Remove unfinished controls or mark unavailable capabilities with a useful reason and supported alternative.
- Freeze the beta client schema set and retain explicit incompatible-version handling.
- Review command payloads for required revision, reason, actor context and idempotency fields.
- Run parity scenarios against native and resolve semantic differences rather than merely matching screen appearance.
- Produce a searchable error-state catalogue with user-facing recovery actions.

Output: completed beta workflow/parity matrix, frozen schema set, decision-payload audit, and searchable error/recovery catalogue.

Verification: every mandatory workflow and error state has reproducible evidence; unavailable controls explain supported alternatives, incompatible schemas fail explicitly, and web/native agree on revisions, command outcomes, provenance, and scoring semantics.

### WEB-M5-02: Foreground performance and load

**Dependencies:** [WEB-M4-06](m4.md#web-m4-06-scalable-authoring-and-comparison-ui), [WEB-M4-09](m4.md#web-m4-09-expand-3d-quality-within-bounded-rendering).

**Required inputs:** BE-M5-01 workload/hardware definitions and complete candidate workflows.

**Planned blockers / completion gates:** Final P1 and P2 correctness/recovery/resource gates require raw foreground traces; minimized renderers, dropped durable events or hidden backlog cannot manufacture a pass.

- Benchmark P1 with exactly 5,000 graph edges and web/native connected simultaneously; P2 uses 50 shuttles, exactly 10,000 edges and ten subscribers comprising two real clients and eight harness subscribers.
- Collect frame-duration, main-thread long-task, state-age and command-lifecycle distributions; report p95/p99 rather than averages alone.
- Bound worker input/output queues, route preview work, history cache, textures and geometry.
- Coalesce replaceable state updates while preserving all durable incident, decision and reservation events.
- Use level of detail, instancing and viewport-aware layers where measurements show rendering cost.
- Apply controlled visual degradation under overload while keeping input, stale-state indicators and incident actions responsive.
- Report foreground and background behaviour separately; do not hide backlog by discarding authoritative events.

Output: reproducible P1/P2 browser benchmark, raw percentile/long-task traces, queue/cache limits, and measured visual-degradation and supported-load policy.

Verification: all mandatory P1 gates and P2 correctness, recovery, and bounded-resource checks pass on the exact workloads; overload never discards durable events or hides stale state, and indicative P2 speed misses are reported with the measured support envelope.

### WEB-M5-03: Endurance and resource lifecycle

**Dependencies:** [WEB-M4-06](m4.md#web-m4-06-scalable-authoring-and-comparison-ui), [WEB-M4-09](m4.md#web-m4-09-expand-3d-quality-within-bounded-rendering).

**Required inputs:** WEB-M5-02 resource counters and two-hour mixed-workflow script.

**Planned blockers / completion gates:** Needs bounded heap/GPU/workers/sockets through repeated sessions and context loss; stale assets or resource growth beyond defined limits block acceptance.

- Run long shifts with repeated route editing, incident inspection, branch comparison, reports and session switching.
- Measure heap, GPU/geometry counters, live workers, pending requests, sockets and listener growth after warm-up.
- Verify cache eviction by revision and session; asset reuse must not leak one session's state into another.
- Destroy cancelled preview resources and unused render targets without disposing geometry still used by an active view.
- Test WebGL context loss and recovery; preserve textual controls, pending command status and stored session identity.
- Suspend heavy rendering for hidden tabs and recover from a verified baseline on return.

Output: two-hour P1 mixed-workflow soak report, repeated lifecycle/resource graphs, revision-aware eviction/disposal, and WebGL/background recovery evidence.

Verification: post-warm-up resource use meets canonical ceilings/plateau criteria, cancelled resources are reclaimed without breaking active views, and context loss or hidden-tab return preserves session/command identity and recovers from verified state without cross-session leaks.

### WEB-M5-04: Network and concurrency resilience

**Dependencies:** [WEB-M3-02](m3.md#web-m3-02-route-deployment-and-shared-session-conflicts), [WEB-M3-06](m3.md#web-m3-06-mvp-performance-and-recovery).

**Required inputs:** BE-M5-03/04 fault scenarios, role changes and paired native/multi-tab actors.

**Planned blockers / completion gates:** Faults at every command boundary must converge without replacement approvals, replay gaps or cross-session mutation; recovered queued work requires explicit review.

- Inject latency, loss, disconnects, repeated responses and reordered snapshots under documented conditions.
- Recover from baseline loss, expired history retention and backend restart with clear resynchronisation.
- Keep an uncertain command pending until reconciliation or explicit server resolution; do not auto-create a replacement mutation.
- Present recovered queued commands requiring reconfirmation without silently resubmitting them or causing delayed approval.
- Test several tabs and paired native/web actors modifying one session, including trainer/trainee permission differences.
- Reject stale route deployments, expired incident candidates and obsolete charging plans while preserving editable drafts.
- Rate-limit local retries with bounded backoff and avoid reconnect storms across multiple clients.
- Confirm local replay inspection cannot pause or rewind another user's active session.

Output: fault-injection/concurrent-actor matrix, bounded retry/resync handling, durable command reconciliation, and visible reconfirmation/conflict states.

Verification: loss at each acceptance/application boundary causes no duplicate or surprise approval; restart, retention expiry, reordered snapshots, and permission changes converge to authorised backend state. Stale drafts remain editable but require revalidation, and local replay cannot alter the shared clock.

### WEB-M5-05: Accessibility and visual quality

**Dependencies:** [WEB-M5-01](m5.md#web-m5-01-feature-completion-and-contract-freeze).

**Required inputs:** Supported browser/DPI/theme matrix and keyboard/screen-reader scripts.

**Planned blockers / completion gates:** Blocking focus, contrast, pointer-only controls or repeated historical alerts must be fixed and retested across the complete workflow.

- Audit both themes for text contrast, focus visibility, non-colour status, at least 14 px body text and readable dense tables.
- Complete keyboard alternatives for route vertices, polygon editing, charging timelines, incident choices and replay controls.
- Test focus restoration after dialogs, virtualised lists and asynchronous validation.
- Use restrained live-region announcements for critical state changes without narrating every position update.
- Provide reduced-motion behaviour, optional audio and deduplicated alerts across reconnect/replay.
- Validate zoom, supported responsive layouts and high-DPI rendering on the declared browser matrix.
- Capture visual regressions for empty, loading, stale, conflicting, rejected, completed and unavailable states.

Output: accessibility audit, complete keyboard alternatives, tested responsive/theme/DPI layouts, restrained alerts, and visual-regression fixtures for all listed UI states.

Verification: keyboard and screen-reader users complete route-to-report tasks without pointer-only controls, hidden focus, or colour/audio-only information; async updates preserve focus, reconnect/replay does not repeat historical alerts, and blocking accessibility defects are resolved.

### WEB-M5-06: Release diagnostics and build discipline

**Dependencies:** [WEB-M5-01](m5.md#web-m5-01-feature-completion-and-contract-freeze).

**Required inputs:** Sanitized diagnostics policy, CI/display setup and backend deployment/compatibility contracts.

**Planned blockers / completion gates:** Needs passing production checks and upgrade/rollback rehearsal with retained sessions; stale caches or credential-bearing diagnostics block completion.

- Provide opt-in diagnostic bundles containing timings, revision IDs and sanitised error context; omit unnecessary trainee personal data.
- Separate product reports from development traces and document their retention/export behaviour.
- Verify production asset paths, cache invalidation and server/client schema mismatch during deployment.
- Run type-check, unit/contract/integration suites and production build in CI.
- Document reproducible local startup and the supported offline/local-server training mode if that deployment is included.
- Rehearse upgrade and rollback against a retained session without assuming cached assets match the backend.

Output: opt-in sanitised diagnostics, report/trace retention guidance, passing production CI artifacts, reproducible startup instructions, and candidate upgrade/rollback rehearsal.

Verification: type-check, unit/contract/integration tests, and production build pass on the candidate commit; diagnostics omit credentials/unnecessary personal data, deployment cache/schema mismatch is actionable, and upgrade/rollback preserves or safely rejects incompatible retained-session state.

### WEB-M5-07: Meet full-scene 3D rendering budgets

**Dependencies:** [WEB-M5-02](m5.md#web-m5-02-foreground-performance-and-load), [WEB-M4-09](m4.md#web-m4-09-expand-3d-quality-within-bounded-rendering).

**Required inputs:** Frozen 3D quality/camera/content profile and paired native renderer.

**Planned blockers / completion gates:** Must measure real CPU/GPU/render-resource costs and preserve picks/operational objects; mandatory 3D P1 and P2 correctness/resource/recovery gates cannot use flat substitutes.

- Profile paired-client P1/P2 with exact 3D content, required viewports, camera path and foreground resolution/quality settings.
- Measure main-thread/worker costs, GPU time where available, draw calls, submitted triangles, render-target/texture bytes and long frames separately.
- Optimise instancing/culling/LOD and bounded upload scheduling with before/after spatial correctness results.
- Keep operational objects, stable picks, stale-state indicators and incident evidence available during permitted P2 visual degradation.

Output: reproducible full-3D benchmark, profiling-led renderer changes and supported-load/quality report.

Verification: mandatory 3D P1 and P2 correctness/recovery/resource gates pass; unloaded/minimized/flat views cannot establish a pass, and indicative P2 speed misses are disclosed with the measured envelope.

### WEB-M5-08: Harden 3D asset and context lifecycle

**Dependencies:** [WEB-M5-03](m5.md#web-m5-03-endurance-and-resource-lifecycle), [WEB-M5-04](m5.md#web-m5-04-network-and-concurrency-resilience).

**Required inputs:** BE-M5-08 scene fault fixtures and pinned readiness/fallback rules.

**Planned blockers / completion gates:** Two-hour scene/context churn must prove bounded ownership and correct recovery; mandatory corruption, stale uploads or duplicate approvals block acceptance.

- Inject wrong hashes, unsupported features, oversized decoded assets, missing mandatory geometry and optional high-detail failures.
- Stress worker decode/cancellation, staging/upload limits and shared-asset reference disposal during scene/session/branch changes.
- Recover WebGL context from the pinned manifest and verified session state while textual command reconciliation/live alerts remain usable.

Output: 3D asset/context fault suite, verified readiness/recovery flow and resource/worker/socket plateau evidence.

Verification: stale jobs cannot populate a new scene, required content failure is explicit, optional detail uses only declared fallback assets, and recovery causes neither leaked resources nor duplicate/surprise approvals.

### WEB-M5-09: Close spatial and 3D interaction regressions

**Dependencies:** [WEB-M5-05](m5.md#web-m5-05-accessibility-and-visual-quality), [WEB-M5-07](m5.md#web-m5-07-meet-full-scene-3d-rendering-budgets), [WEB-M5-08](m5.md#web-m5-08-harden-3d-asset-and-context-lifecycle).

Verification: exact IDs and canonical tolerances pass, camera movement cannot submit edits, required controls remain operable, and no spatially invalid or unverified candidate is presented as approved.

## Additional 3D exit criteria

- The complete product passes required gates with both primary 3D worlds visible under frozen content/quality settings.
- Two-hour scene/asset/context churn proves bounded resources, valid readiness and durable command/provenance recovery.
- Spatial, selection and 3D accessibility regressions are closed; fallback usability cannot substitute for successful normal 3D operation.

## Verification and failure cases

- Complete the P1 and P2 matrices with raw traces and the exact fixture/build/machine configuration.
- Run the specified endurance duration and repeated view/session transitions; demonstrate bounded memory after warm-up.
- Disconnect immediately before and after acceptance/application to exercise every command uncertainty window.
- Lose WebGL while a command is pending; the textual ledger must still reconcile correctly.
- Run a screen-reader and keyboard-only exercise from route preparation through report download.
- Trigger auth expiry or role revocation mid-session; retain historical visibility only as the server permits.
- Assert no obsolete scene, alert, report or async response crosses a session epoch.

## Deliverables and exit evidence

- Feature-complete beta candidate, known limitation catalogue and supported environment matrix.
- Performance report containing all target results, failures and measured degradation boundaries.
- Recovery/endurance recordings, resource graphs and cross-client conflict traces.
- Accessibility audit with defects, fixes and any remaining documented limitations.
- Reproducible CI/build evidence tied to the candidate commit.
- Release readiness checklist with an owner and disposition for every unresolved defect.

M5 exits when core workflows, mandatory P1 gates, and P2 correctness, recovery, and bounded-resource checks pass, with no unresolved critical loss-of-state or duplicated-command defect. P2 speed targets remain indicative; report measured supported capacity and degradation explicitly. Averages or a single smooth demonstration are not sufficient evidence.
