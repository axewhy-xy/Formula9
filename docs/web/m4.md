# M4: Advanced training and explainable comparisons

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks/handoffs remain unchanged. WEB-M4-07 through WEB-M4-09 and the additional exit criteria extend them under the [mandatory 3D contract](../three_d_simulation.md). Primary 3D is required from M2; 2D panels/minimaps and accessible fallback support but cannot replace it. New tasks remain planned until verified.

## Outcome and scope

Trainers can construct reusable multi-event shifts and review recurring decision patterns. Trainees can compare defensible alternatives and understand how routing, battery and service coverage interact.

Advanced local manoeuvres are available only in curated scenarios whose backend advertises the required lane/conflict model. Optional recorded perception inspection has an independent capability gate and cannot delay the core milestone.

Dependencies: [web M3](m3.md), [backend M4](../backend/m4.md), [native M4](../native/m4.md), versioned training/rubric capabilities and updated performance fixtures.

## Tasks

### WEB-M4-01: Advanced shift authoring

**Dependencies:** [WEB-M3-05](m3.md#web-m3-05-minimum-trainer-authoring-and-persistent-debrief), [BE-M4-01](../backend/m4.md#be-m4-01-extend-scenario-authoring-with-validated-dependencies), [BE-M4-02](../backend/m4.md#be-m4-02-improve-fleet-interaction-and-operational-consequences).

**Required inputs:** Timeline trigger contracts and isolated rehearsal sessions.

**Planned blockers / completion gates:** Invalid trigger graphs or required assets block publication; variants/rehearsals cannot mutate active trainee attempts.

- Add multi-event scenario timelines for disruptions, incident triggers, charger maintenance and fleet availability.
- Edit prerequisites and trigger relationships with validation for cycles, unreachable triggers and conflicting initial conditions.
- Support parameterised scenario variants with explicit permitted ranges and reproducible seed selection.
- Clone immutable published scenarios into drafts; compare revisions and preview affected routes, incidents and rubric dimensions.
- Provide trainer rehearsal using a separate session so testing a scenario does not alter trainee records.
- Show asset/capability availability before publication, including missing graph, history or optional media dependencies.

Output: multi-event timeline authoring, validated trigger dependencies, reproducible scenario variants, revision comparison, and isolated trainer rehearsal.

Verification: cyclic/unreachable triggers, impossible initial constraints, and missing required assets block publication with actionable errors; permitted seeds/ranges reproduce the fixture, and rehearsal/editing cannot modify published revisions or trainee records.

### WEB-M4-02: Reference solutions and transparent scoring

**Dependencies:** [WEB-M3-05](m3.md#web-m3-05-minimum-trainer-authoring-and-persistent-debrief), [WEB-M3-08](m3.md#web-m3-08-review-3d-history-branches-and-synthetic-cameras), [BE-M4-04](../backend/m4.md#be-m4-04-make-replay-and-branch-comparison-auditable), [BE-M3-05](../backend/m3.md#be-m3-05-persist-debrief-score-explanations-and-exports).

**Required inputs:** Accepted reference decisions, rubric calculations and comparison alignment.

**Planned blockers / completion gates:** Needs compatible recorded outcomes with explicit unavailable results; revised rubrics cannot overwrite original assessments or hide safety failures.

- Display multiple accepted reference responses when the rubric permits trade-offs rather than implying one fastest answer is always correct.
- Compare trainee and reference outcomes across response time, constraint violations, stop/service coverage, detour efficiency and battery reserve.
- Explain each awarded/deducted component using stored evidence, criterion identifier and rubric revision.
- Present simulated reference branches with their own world/seed/decision provenance and alignment point.
- Expose missing reference results or model limitations without presenting an estimated score as final.
- Keep score changes tied to an explicit rubric version; do not retroactively overwrite a completed training record.

Output: trainee/reference comparison with criterion-level calculation evidence, multiple accepted alternatives, branch provenance, and explicit unavailable-result states.

Verification: shared rubric fixtures reproduce stored awarded/deducted components and accepted trade-offs; missing references remain unavailable, safety failures cannot be concealed by timing points, and a revised rubric cannot silently replace the original assessment record.

### WEB-M4-03: Debrief patterns and trainer review

**Dependencies:** [WEB-M3-05](m3.md#web-m3-05-minimum-trainer-authoring-and-persistent-debrief), [BE-M4-05](../backend/m4.md#be-m4-05-explain-assessment-patterns-across-attempts).

**Required inputs:** Role-scoped filters, sample denominators and evidence drill-down/export contracts.

**Planned blockers / completion gates:** Counts, filters and exported records must agree; incompatible rubrics and missing data need explicit presentation, not silently merged comparisons.

- Add filters by scenario, trainee alias, incident type, outcome and attempt while respecting backend role permissions.
- Show repeated patterns such as delayed escalation, invalid first detours or avoidable coverage gaps with sample counts.
- Distinguish observed outcomes, rubric interpretation and trainer notes in the presentation.
- Drill from an aggregate to the exact incidents and recorded reasons supporting it.
- Compare attempts on consistent scenario/rubric revisions, warning when versions differ.
- Export the filtered review with provenance, applied filters and missing-data notes.

Output: permission-scoped trainer filters, sample-aware pattern views, incident drill-down, compatible-attempt comparison, and filtered exports.

Verification: aggregate counts, underlying incidents, and exported filters agree for populated, empty, and incomplete groups; differing rubric versions are flagged, notes remain distinct from observed evidence, and restricted trainee details are not disclosed.

### WEB-M4-04: Curated constrained manoeuvre review

**Dependencies:** [WEB-M3-03](m3.md#web-m3-03-concurrent-incident-triage-and-replay), [WEB-M3-07](m3.md#web-m3-07-complete-surface-aware-3d-authoring), [BE-M4-03](../backend/m4.md#be-m4-03-gate-any-local-rule-exception-manoeuvre).

**Required inputs:** Capability/lane revision and bounded visibility/envelope overlays.

**Planned blockers / completion gates:** Conditional: enable only after the backend manoeuvre gate passes. Otherwise show unsupported state with road detour/wait/escalation; core M4 does not wait for local passing.

- Discover capability and lane-model revision before exposing a local pass-around-obstacle option.
- Draw lane boundaries, permitted conflict areas, obstruction, visibility limitation and the candidate's validation footprint.
- Explain the backend's rejection or permitted training exception without making the client a driving controller.
- Require current candidate validity, scenario permission, reason and expected revisions before requesting the decision.
- Treat unknown clearance, inadequate visibility, collision risk or physical-fit failure as unavailable; a named training rule exception cannot bypass these checks.
- Invalidate the option when occupancy, visibility, relevant geometry or incident revision changes.
- Keep road-network detour, wait and escalation available when the local manoeuvre capability is absent.
- Never enable a manoeuvre because a rendered line appears clear or a trainee has written an approval reason.

Output: backend-capability-gated manoeuvre review with lane/visibility/validation overlays, training-exception explanation, and revision-bound decision controls; unsupported scenes retain network alternatives.

Verification: ordinary graph-only scenes cannot enable local passing; unknown clearance, inadequate visibility, collision/fit failure, and changed/expired proposals prevent approval despite a written reason or exception. A curated accepted case requires final backend validation, not visual inference.

### WEB-M4-05: Optional recorded perception inspection

**Dependencies:** [WEB-M3-08](m3.md#web-m3-08-review-3d-history-branches-and-synthetic-cameras).

**Required inputs:** Explicit scope approval, accepted core M4 workflow and independent recorded-perception capability with source/calibration/model metadata.

**Planned blockers / completion gates:** Optional: unavailable models/media or missing provenance blocks this panel, not core delivery. Record a disabled/deferred disposition; no client inference or synthetic camera substitution.

- Enable only if the independent backend capability is available and the core M4 workflow is accepted.
- Display immutable recorded sequence/frame, original geographic source, calibration and model revisions.
- Present derived detections as model outputs and uncertainty as source-defined information; do not invent safety probabilities.
- Keep camera/overlay loading off the live fleet stream and within bounded asset caches.
- Do not show KITTI camera frames as the view of a Singapore scenario or extend them beyond a simulated branch boundary.
- Make missing media, unavailable models or optional-service failure local to the inspection panel.

Output: an independently gated recorded-perception panel with source/calibration/model metadata and bounded asset loading, or an explicit deferred/disabled capability without a core dependency.

Verification: when included, detections remain labelled model outputs, recordings retain actual geography/time and branch limits, and missing media/models affect only the panel. If omitted, all mandatory M4 workflows remain complete and the package does not advertise the panel as delivered.

### WEB-M4-06: Scalable authoring and comparison UI

**Dependencies:** [WEB-M3-06](m3.md#web-m3-06-mvp-performance-and-recovery), [WEB-M3-08](m3.md#web-m3-08-review-3d-history-branches-and-synthetic-cameras).

**Required inputs:** WEB-M4-01/02/03 list/comparison workloads and BE-M4-06 timing profiles.

**Planned blockers / completion gates:** Final evidence requires bounded views/workers and preserved accessible focus under rich workloads; P1 must pass and P2 limits must be measured.

- Virtualise large incident/review lists while maintaining keyboard focus and screen-reader item context.
- Perform expensive history preparation and aggregate presentation transforms outside animation-critical work.
- Share immutable scene geometry across branch views without sharing mutable world state.
- Budget and dispose comparison cameras, render targets and textures when panels close.
- Instrument route edit response, branch load, authoring validation and aggregate query time separately.
- Preserve P1 latency/frame gates and publish initial P2 stress results before committing further feature expansion.

Output: accessible virtualised review lists, off-main-thread heavy preparation, isolated comparison state, resource disposal, and instrumented P1/P2 comparison workloads.

Verification: repeated branch/panel creation and closure respects declared geometry/texture/worker bounds without corrupting another view; focus survives virtualisation, mandatory P1 gates remain passing, and exploratory P2 results document measured limits and prioritised defects.

### WEB-M4-07: Rehearse richer 3D scene variants

**Dependencies:** [WEB-M4-01](m4.md#web-m4-01-advanced-shift-authoring), [WEB-M3-07](m3.md#web-m3-07-complete-surface-aware-3d-authoring), [BE-M4-08](../backend/m4.md#be-m4-08-validate-richer-authored-3d-environments).

**Required inputs:** Dimensioned variant packages and object/proxy diagnostic contracts.

**Planned blockers / completion gates:** Invalid support/proxy transforms must stay unpublished; rehearsal selection and assets must remain tied to a separate scene/attempt identity.

- Extend trainer scenario composition with reusable dimensioned obstacles, road-level placement and seeded environment variants from validated scene packages.
- Provide live-versus-rehearsal scene identity, per-object change review and preview without modifying trainee attempts.
- Use bounds/support/proxy diagnostics to explain invalid spatial variants before publication.
- Retain 3D focus, lists and keyboard alternatives for objects hidden behind geometry.

Output: richer 3D authoring/rehearsal workspace, variant/scene diff presentation and shared invalid-placement fixtures.

Verification: bad transforms, unsupported surfaces and proxy mismatches remain unpublished; changing or rehearsing a variant leaves active/retained attempts unchanged and all selections refer to the correct scene revision.

### WEB-M4-08: Explain 3D visibility and branch consequences

**Dependencies:** [WEB-M4-02](m4.md#web-m4-02-reference-solutions-and-transparent-scoring), [WEB-M3-08](m3.md#web-m3-08-review-3d-history-branches-and-synthetic-cameras), [BE-M4-07](../backend/m4.md#be-m4-07-produce-bounded-3d-visibility-and-spatial-evidence), [BE-M4-09](../backend/m4.md#be-m4-09-explain-spatial-outcomes-in-comparison-and-debrief).

**Required inputs:** Observation origins, revisioned spatial predicates and compatible branch anchors.

**Planned blockers / completion gates:** Camera visibility cannot override backend unknown/blocked results; stale overlays and mismatched branch evidence block acceptance.

- Display backend observation origins, blockers, range/coverage and unknown visibility separately from the current orbit camera.
- Align compatible branch poses/paths with ghost geometry and incident anchors, linking spatial predicates to debrief evidence.
- Invalidate overlays when geometry/obstacle revisions change and preserve conditional local-manoeuvre/perception gates.
- Label diagnostics that intentionally reveal hidden geometry so they are not mistaken for what a shuttle sensed.

Output: source-labelled spatial evidence overlays, 3D branch comparison and revision-aware constraint drill-down.

Verification: looking around an obstruction cannot change a blocked/unknown backend result; stale/unsupported manoeuvres remain unavailable, and every displayed spatial consequence resolves to the matching backend record and scene.

### WEB-M4-09: Expand 3D quality within bounded rendering

**Dependencies:** [WEB-M3-09](m3.md#web-m3-09-complete-3d-charging-execution-and-p1-acceptance), [BE-M4-08](../backend/m4.md#be-m4-08-validate-richer-authored-3d-environments).

**Required inputs:** Versioned LOD/material presets, frozen camera script and viewport/resource limits.

**Planned blockers / completion gates:** Richer assets must preserve dimensions and semantic picks. Final P1/P2 rendering evidence includes WEB-M4-07/08 workloads without reducing operational geometry.

- Add richer road/building/operational assets, fixed material/lighting presets, instanced repeated geometry and versioned LOD tiers.
- Test depth fighting, transparency, clipping, route/label occlusion and selected-object readability through the frozen camera script.
- Bound branch render targets, texture/decode/upload work and active viewports; quality changes never alter operational proxies.
- Record full 3D P1 regression and initial P2 traces with exact content and quality settings.

Output: richer scene renderer/quality presets, depth/readability fixtures and 3D P1/P2 render/resource report.

Verification: geometry scale, semantic picks and backend outcomes remain unchanged across LOD/light settings; mandatory P1 passes, closed views release their resources, and P2 measurements honestly describe supported limits.

## Additional 3D exit criteria

- Advanced authoring, evidence and comparison operate in the already-required 3D world rather than introducing it as an optional enhancement.
- Observation-origin/coverage and branch/scene identity remain correct under richer geometry and occlusion.
- P1 stays passing with the richer frozen content; P2 traces include real rendering and optional capabilities remain independently gated.

## Verification and failure cases

- Publish scenarios with missing assets, cyclic triggers and impossible charging constraints; verify actionable validation.
- Review a session against a changed rubric and confirm its original score remains traceable.
- Verify aggregate filters and drill-down records agree, including empty groups and incomplete sessions.
- Attempt a constrained manoeuvre on an ordinary road graph; the UI and backend must reject unsupported use.
- Change relevant world state after candidate generation and verify stale decision protection.
- Open multiple branch comparisons and close them repeatedly; track geometry, texture, worker and memory cleanup.
- Fail the optional perception service and verify route, incident, charging and debrief workflows remain usable.
- Compare the same exercise in web/native and verify semantic agreement for exceptions, score and source labels.

## Deliverables and exit evidence

- Advanced trainer forms, version comparison, rehearsal and multi-event shift demonstrations.
- Reference-versus-trainee debrief and aggregate pattern views linked to actual stored incidents.
- Capability-gated local manoeuvre demonstration on a curated fixture, or an explicit disabled capability with the core M4 accepted.
- Optional perception panel only if its independent gate passes; no hidden core dependency.
- P1 regression evidence, P2 exploratory traces and a prioritised performance defect list.
- Shared cross-client fixtures for advanced authoring, comparison and invalidation.

M4 exits on advanced training, explainable scoring and robust comparison. Experimental media or manoeuvre presentation cannot replace the core evidence.
