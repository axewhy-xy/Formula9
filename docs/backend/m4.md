# M4: Rich scenarios, defensible decisions, and debrief analysis

Task planning notes use the [dependency and blocker conventions](../milestones.md#task-dependencies-and-issue-creation). Dependencies name prerequisite artifacts; final paired evidence is a shared acceptance gate, not a reason to serialize client development.

3D extension (27 October 2026): existing tasks and handoffs are preserved. The added BE-M4-07 through BE-M4-09 tasks and additional exit criteria are cumulative; follow the [mandatory 3D contract](../three_d_simulation.md) and [3D performance/spatial gates](../performance.md#8-3d-workload-and-spatial-acceptance). New tasks remain planned until verified.

Status: planned. Depends on the M3 complete workflow and acceptable P1 latency. M4 adds training depth while retaining the same authoritative runtime and contracts.

The principal outcome is a set of authored shifts in which several operational decisions can be reasonable, their consequences are reproducible, and the debrief explains the tradeoffs.

## BE-M4-01: Extend scenario authoring with validated dependencies

**Dependencies:** [BE-M3-04](m3.md#be-m3-04-add-minimum-trainer-authoring-and-assignment), [BE-M3-02](m3.md#be-m3-02-complete-in-trip-decision-management), [BE-M3-03](m3.md#be-m3-03-implement-battery-and-charging-operations).

**Required inputs:** Curated trigger graphs, permitted seed/range variants and scenario package limits.

**Planned blockers / completion gates:** Dry-run/publication must reject cycles, impossible resource requirements and missing mandatory assets while preserving immutable prior revisions.

- Add reusable incident templates, timed and condition-based triggers, controlled random variants, and difficulty parameters such as simultaneous incidents or reduced charger availability.
- Represent trigger dependencies explicitly and reject impossible cycles, missing entities, contradictory hard constraints, and unreachable required outcomes.
- Provide a headless dry-run validator that checks scenario completion, resource feasibility, and reference decisions before publication.
- Preserve immutable published revisions, source manifests, content hashes, schema versions, and asset references.
- Import/export scenario packages with safe path handling, size limits, supported version checks, and clear diagnostics for unavailable media.

Output: richer authoring APIs, scenario package format, validation reports, and a diverse curated exercise set.

Verification: seed replay, invalid dependency graphs, broken assets, mutually exclusive requirements, and unpublished edits are covered by reproducible fixtures.

## BE-M4-02: Improve fleet interaction and operational consequences

**Dependencies:** [BE-M3-01](m3.md#be-m3-01-complete-pre-trip-planning-and-validation), [BE-M3-02](m3.md#be-m3-02-complete-in-trip-decision-management), [BE-M3-03](m3.md#be-m3-03-implement-battery-and-charging-operations).

**Required inputs:** Declared demand/dwell parameters, planning horizon and sensitivity fixtures.

**Planned blockers / completion gates:** Future-window/resource invariants and reproducible service consequences are required; unsupported optimality or unbounded planning cannot substitute for feasible alternatives.

- Add calibrated stop dwell and passenger-demand abstractions sufficient to explain service coverage and headway consequences; state their simplifications in the scenario manifest.
- Model simultaneous route changes, delayed depot returns, charger outages, queueing, swap failures, and service recovery through deterministic transitions.
- Validate plans against future disruption windows and resource reservations rather than only the current snapshot.
- Maintain bounded planning horizons and return feasible alternatives or explicit infeasibility, without promising optimal fleet scheduling.
- Explain whether a consequence follows from a hard rule, estimated timing, energy model, or scenario-authored assumption.

Output: richer operational model, documented parameters, multi-incident shift fixtures, and model sensitivity reports.

Verification: no vehicle occupies two assignments, no charger serves overlapping reservations, energy remains within physical model bounds, and stops/coverage metrics agree with the event history.

## BE-M4-03: Gate any local rule-exception manoeuvre

**Dependencies:** [BE-M3-07](m3.md#be-m3-07-validate-surface-aware-routes-and-volume-clearance), [BE-M3-02](m3.md#be-m3-02-complete-in-trip-decision-management), [BE-M4-07](m4.md#be-m4-07-produce-bounded-3d-visibility-and-spatial-evidence).

**Required inputs:** Curated lane widths/transitions, occupancy, swept envelopes and scenario exception policy.

**Planned blockers / completion gates:** Conditional capability: missing clearance/visibility or failed abort/revalidation tests blocks enabling local manoeuvres only. Deliver an explicit disabled manifest and detour/wait/escalation alternative when evidence is unavailable.

- Treat opposite-lane passing in the concept image as a separately gated simulator capability, not a routine graph reroute.
- Require curated lane identity/width, boundaries, permitted transition zones, vehicle swept envelope, visibility/occlusion, and opposing-traffic occupancy for the selected micro-scene.
- Separate non-overridable collision/clearance/visibility checks from explicitly configured training-rule exceptions.
- Generate a bounded candidate path and check its predicted occupancy over time; revalidate at application and enforce a deterministic abort/stop policy if assumptions fail.
- Bind approval to the exact manoeuvre, spatial/time limits, incident, scenario permissions, revision, expiry, and recorded reason.
- If required geometry or checks are unavailable, return a non-approvable option with an explanation; the supported exercise uses wait, escalation, or validated road-level detour.

Output: either a validated local-manoeuvre micro-scene with test evidence or an explicit capability-disabled manifest and supported alternative. Full traffic simulation is not a prerequisite.

Verification: hidden oncoming vehicle, inadequate clearance, stale occupancy, missing visibility, expired exception, and changed incident all prevent unsafe application within the model.

## BE-M4-04: Make replay and branch comparison auditable

**Dependencies:** [BE-M3-02](m3.md#be-m3-02-complete-in-trip-decision-management), [BE-M3-09](m3.md#be-m3-09-persist-and-replay-the-complete-3d-state).

**Required inputs:** Pinned branch lineage, clock mappings, source coverage and common comparison horizons.

**Planned blockers / completion gates:** Cannot compare or attach media without compatible initialization/scene evidence; branch operations must not mutate parents or live state.

- Persist checkpoint lineage and branch manifests so an instructor can reopen the historical lead-up, selected decision, and alternative simulation.
- Separate immutable source time from session simulation time and active trainee time; expose mappings and discontinuities explicitly.
- Require matching scene/transform and documented initialization before attaching recorded assets to a branch.
- If recorded data cannot establish a complete fleet state, use an authored simulation initialization and label that origin; do not imply a full world reconstruction.
- Compare branch results on a common horizon with the same demand/seed where meaningful; surface unmatched assumptions rather than averaging unlike cases.

Output: provenance-aware comparison endpoints, branch manifests, and replay export bundles.

Verification: recorded camera frames stop at their real coverage boundary; historic simulated runs remain labelled simulated; a branch never mutates its parent or the live session.

## BE-M4-05: Explain assessment patterns across attempts

**Dependencies:** [BE-M3-04](m3.md#be-m3-04-add-minimum-trainer-authoring-and-assignment), [BE-M3-05](m3.md#be-m3-05-persist-debrief-score-explanations-and-exports).

**Required inputs:** Classification versions, cohort/missing-data rules and access/retention policy.

**Planned blockers / completion gates:** Aggregates must reconcile to contributing records and separate rubric versions; unauthorized trainee access or misleading sample denominators block acceptance.

- Aggregate repeated wrong-way attempts, late responses, reserve violations, missed stops, and avoidable service loss using explicit, versioned classification rules.
- Preserve drill-down from each pattern to the contributing event and rubric criterion.
- Support instructor review of several acceptable reference choices and explain why an apparently faster option scores differently.
- Define cohort filters, missing-data rules, and minimum sample presentation; do not claim validated learning improvements from small internal trials.
- Restrict access to trainee-level records and permit controlled retention/export under the project’s assessment policy.

Output: debrief-pattern queries, cohort summary schema, reproducible scoring examples, and instructor review fixtures.

Verification: aggregation equals the underlying records; deleted/retained attempts follow policy; rubric versions are never mixed silently; learner identity is not exposed to unauthorized sessions.

**Required inputs:** Authored observation origins, proxy coverage, revision keys and bounded query limits.

**Planned blockers / completion gates:** Visibility must come from backend geometry/coverage, not orbit cameras. Unknown, stale or timed-out evidence cannot authorize manoeuvres.

- Add immutable indexed proxy queries from authored observation origins with range, blocker IDs, coverage and model revision.
- Distinguish operator-camera visibility, synthetic onboard rendering and backend visibility evidence; unknown coverage stays unknown.
- Provide explainable blocked/clear/unknown fixtures and invalidate evidence when relevant obstacle/scene revisions change; keep local passing under BE-M4-03's independent gate.

Output: bounded visibility/evidence service, query limits, origin/proxy metadata and occlusion fixtures.

Verification: a building-hidden obstacle or oncoming object remains blocked/unknown from the declared observation origin even when the orbit camera sees it; timeouts and stale geometry cannot enable a manoeuvre.

## BE-M4-09: Explain spatial outcomes in comparison and debrief

**Dependencies:** [BE-M4-04](m4.md#be-m4-04-make-replay-and-branch-comparison-auditable), [BE-M4-05](m4.md#be-m4-05-explain-assessment-patterns-across-attempts), [BE-M4-07](m4.md#be-m4-07-produce-bounded-3d-visibility-and-spatial-evidence), [BE-M4-08](m4.md#be-m4-08-validate-richer-authored-3d-environments).

**Required inputs:** Spatial predicate/entity references and report schema extensions.

**Planned blockers / completion gates:** Comparisons/exports must resolve to pinned scene/proxy/rubric evidence; unknown visibility or incompatible branch horizons cannot become a verified result.

- Attach obstruction/clearance/visibility predicates, relevant entity IDs, spatial revisions and model assumptions to incident decisions and accepted alternatives.
- Compare branches from compatible 3D checkpoints over the same horizon, preserving each branch's geometry, state and source identity.
- Export structured spatial evidence references and limits with reports, without treating rendered screenshots as authoritative geometry or simulator outcomes as real-world safety proof.

Output: spatial explanation schema, evidence-linked 3D branch/debrief fixtures and versioned report examples.

Verification: clients and exports resolve each result to the same pinned entities/proxies; changed geometry/rubric versions are not mixed, and unknown coverage cannot be presented as verified clearance or visibility.

## Additional 3D exit criteria

- Visibility evidence, richer scene validation and spatial debrief tasks pass while mandatory 3D P1 remains passing.
- AT-18 proves observation-origin/coverage correctness and explicit unknowns; local manoeuvre/perception remain separately gated.
- P2 measurements use real 3D content and identify spatial-query bottlenecks and supported limits.

## M4 exit gate

1. Several varied shifts can be authored, validated, assigned, completed, and compared with understandable score explanations.
2. Alternatives share documented assumptions; provenance and source coverage survive history, replay, branches, and export.
3. Local rule exceptions are either validated in the curated capability or explicitly unavailable; no missing geometry receives a fabricated safety approval.
4. Richer content preserves measured P1 targets and bounded resource use.

Optional recorded-data perception may produce separate evidence overlays only after the above gates. It must not become authoritative simulated-world state or block training workflows.
